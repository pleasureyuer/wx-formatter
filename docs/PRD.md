# PRD - 公众号文章一键排版工具

## 1. 项目信息

| 字段 | 内容 |
|------|------|
| **项目名称** | wx-formatter |
| **语言** | 中文 |
| **技术栈** | Vite + React + MUI + Tailwind CSS |
| **项目类型** | Web 应用（浏览器端使用） |

### 原始需求复述

用户需要一个**公众号文章一键排版 Web 工具**，核心能力：将原始文章内容（Markdown / 纯文本）一键排版为美观的公众号风格，并支持排版后自动推送到微信公众号草稿箱。

---

## 2. 产品定义

### 产品目标

| # | 目标 | 衡量指标 |
|---|------|----------|
| G1 | **降低排版门槛** — 让无排版经验的作者也能快速产出视觉统一、美观的公众号文章 | 从粘贴到预览完成 < 30 秒 |
| G2 | **打通推送链路** — 排版结果一键进入公众号草稿箱，消除"复制-粘贴-调格式"的重复劳动 | 推送成功率 > 99% |
| G3 | **模板可复用** — 提供多套风格模板，用户可快速切换品牌调性 | 模板数 ≥ 5 套，支持自定义 |

### 用户故事

| # | 用户故事 |
|---|----------|
| US1 | 作为**公众号运营者**，我想把写好的 Markdown 文章一键排版为公众号样式，这样我就不用手动调整字体、行距和配色 |
| US2 | 作为**公众号运营者**，我想排版完成后直接推送到草稿箱，这样我就不用复制到微信后台重新调格式 |
| US3 | 作为**多账号运营者**，我想管理多个公众号的 API 配置，这样我可以为不同账号使用不同模板推送 |
| US4 | 作为**品牌运营者**，我想自定义排版模板的颜色和字体，这样输出文章能与品牌视觉保持一致 |
| US5 | 作为**内容创作者**，我想在推送前实时预览排版效果，这样我可以确认最终呈现无误 |

## 3. 技术规范

### 需求池

#### P0 — Must Have（MVP）

| 编号 | 需求 | 说明 |
|------|------|------|
| P0-1 | Markdown 解析与排版 | 支持标准 Markdown 语法（标题、段落、列表、引用、代码块、图片链接等），转换为内联样式的 HTML |
| P0-2 | 排版模板选择 | 提供至少 3 套预设模板（简约白、商务蓝、暖橙），每套包含完整的标题/正文/引用/分割线样式 |
| P0-3 | 实时预览 | 左侧编辑、右侧实时渲染预览，模拟手机屏幕宽度（375px） |
| P0-4 | 一键复制排版结果 | 将排版后的 HTML 复制到剪贴板，可直接粘贴到公众号编辑器 |
| P0-5 | 公众号 API 配置 | 支持填写 AppID + AppSecret，本地加密存储，用于调用草稿箱接口 |
| P0-6 | 推送到草稿箱 | 调用微信公众号 `draft/add` 接口，将排版后的文章推送到草稿箱 |

#### P1 — Should Have

| 编号 | 需求 | 说明 |
|------|------|------|
| P1-1 | 多账号管理 | 支持添加/切换多个公众号配置 |
| P1-2 | 模板自定义 | 用户可调整模板的主色、字号、行距、字间距，并保存为自定义模板 |
| P1-3 | 封面图上传 | 推送时支持设置封面图（thumb_media_id），通过 `media/uploadimg` 接口上传 |
| P1-4 | 文章摘要编辑 | 推送前可编辑摘要（digest），默认取正文前 54 字 |
| P1-5 | 历史记录 | 本地保存最近 20 条排版记录，可快速重新编辑或推送 |

#### P2 — Nice to Have

| 编号 | 需求 | 说明 |
|------|------|------|
| P2-1 | 图片上传与替换 | 将 Markdown 中的图片自动上传到公众号素材库，替换为微信图片 URL |
| P2-2 | 模板市场 | 用户可浏览/使用社区共享的排版模板 |
| P2-3 | 导出 PDF | 将排版后的文章导出为 PDF 文件 |
| P2-4 | 快捷键支持 | 常用操作支持键盘快捷键（如 Ctrl+Enter 推送） |
| P2-5 | 暗色模式 | 编辑器支持暗色主题切换 |

## 4. UI 设计说明

### 页面结构

应用采用**单页布局**，核心区域划分如下：

```
┌─────────────────────────────────────────────────┐
│  顶部导航栏（Logo + 模板选择器 + 推送按钮）       │
├──────────────────────┬──────────────────────────┤
│                      │                          │
│   左侧：编辑区       │   右侧：预览区            │
│   - Markdown 输入    │   - 手机模拟框 (375px)    │
│   - 工具栏（加粗等） │   - 实时渲染排版效果       │
│                      │                          │
├──────────────────────┴──────────────────────────┤
│  底部状态栏（字数统计 + 保存状态 + 错误提示）      │
└─────────────────────────────────────────────────┘
```

### 核心交互流程

```
粘贴/输入 Markdown
       │
       ▼
  选择排版模板 ──────► 实时预览更新
       │
       ▼
  确认预览效果
       │
       ├──► 「复制 HTML」→ 粘贴到公众号后台
       │
       └──► 「推送到草稿箱」
                │
                ▼
         检查 API 配置 ──(未配置)──► 弹出配置弹窗
                │                        │
              (已配置)              填写 AppID/AppSecret
                │                        │
                ▼                        ▼
         输入标题/摘要/封面  ◄────────────┘
                │
                ▼
         确认推送 → 成功提示
```

### 关键组件说明

| 组件 | 说明 |
|------|------|
| **编辑器** | 基于 textarea 的 Markdown 编辑区，顶部提供简易工具栏（标题、加粗、列表、引用、分割线） |
| **预览区** | 以 375px 宽度模拟手机屏幕，应用所选模板的内联样式渲染 HTML |
| **模板选择器** | 导航栏中的下拉选择器，切换模板后预览区实时刷新 |
| **推送弹窗** | Dialog 弹窗，包含标题（必填）、摘要、封面图上传、目标账号选择、确认推送按钮 |
| **API 配置弹窗** | Dialog 弹窗，填写 AppID / AppSecret，支持"测试连接"按钮验证配置有效性 |

## 5. 待确认问题

| # | 问题 | 影响 | 建议 |
|---|------|------|------|
| Q1 | 公众号 AppSecret 属于敏感信息，前端存储是否有合规风险？ | P0-5 | 建议使用 localStorage 加密存储，并在 UI 中给出安全提示；长期考虑增加后端中转 |
| Q2 | 微信公众号 API 要求服务器 IP 白名单，纯前端应用无法直接调用，是否需要后端代理？ | P0-6 | **关键阻塞项**。微信公众号 `draft/add` 等接口要求从服务器端调用并设置 IP 白名单，纯前端无法直接调用。需要确认：是否增加轻量后端（如 Cloudflare Workers / Vercel Serverless）做 API 代理 |
| Q3 | 排版后的 HTML 是否需要兼容其他平台（如知乎、头条）？ | P1-2 | 如需多平台兼容，模板样式需做适配层 |
| Q4 | 预设模板的视觉风格是否有参考对象或品牌规范？ | P0-2 | 需要用户提供风格参考或品牌色值 |
| Q5 | 是否需要支持协作编辑（多人同时排版）？ | P2 | 如需要，需引入实时同步机制，显著增加复杂度 |

> **特别注意 Q2**：微信公众号后台 API 的调用必须在服务器端完成（需配置 IP 白名单获取 access_token），这意味着纯前端方案无法直接实现"推送到草稿箱"功能。建议 MVP 阶段采用以下方案之一：
> - **方案 A**：增加轻量 Serverless 函数作为 API 代理（推荐）
> - **方案 B**：MVP 先只做「一键复制 HTML」，推送功能后续迭代
